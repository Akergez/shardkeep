# Shardkeep — план реализации MVP 1

## 1. Цель MVP

Выпустить нативное Android-приложение, которое:

- работает с выбранным пользователем каталогом заметок;
- индексирует задачи из Markdown-файлов;
- показывает задачи на день и неделю;
- позволяет создать задачу и изменить её статус;
- создаёт и показывает быстрые заметки и чек-листы;
- выводит задачи, заметки и чек-листы в Android-виджеты;
- локально уведомляет о ближайших задачах;
- не блокирует UI при чтении файлов, индексации и сетевых операциях.

Android — единственная обязательная платформа MVP 1. Общая логика и основной UI разрабатываются в KMP, но специфичные интеграции остаются платформенными.

## 2. Что не входит в обязательный MVP 1

- Wear OS-приложение, Tiles и Complications;
- iOS-приложение и iOS-виджеты;
- desktop-релизы;
- совместная работа нескольких пользователей;
- полный Markdown-редактор;
- поддержка всего синтаксиса emoji/dataview формата задач;
- мгновенная двусторонняя синхронизация;
- Firebase Cloud Messaging: локальным напоминаниям серверный push не нужен;
- публикация в Google Play и App Store.

Эти функции не должны влиять на архитектуру негативно, но не должны блокировать первый Android-релиз.

## 3. Принятые архитектурные решения

### 3.1. Источник истины

Markdown-файлы каталога заметок являются источником истины. Локальная база приложения — только индекс, настройки, состояние синхронизации и конфигурация виджетов.

### 3.2. Доступ к каталогу заметок

Общая логика работает через абстракцию `NotesDirectoryStorage`:

```kotlin
interface NotesDirectoryStorage {
    suspend fun listFiles(): List<NotesDirectoryFile>
    suspend fun read(path: NotesDirectoryPath): NotesDirectoryDocument
    suspend fun write(path: NotesDirectoryPath, expectedVersion: FileVersion?, content: ByteArray)
    suspend fun create(path: NotesDirectoryPath, content: ByteArray)
    suspend fun delete(path: NotesDirectoryPath)
    fun observeChanges(): Flow<NotesDirectoryChange>
}
```

Реализации:

- Android: Storage Access Framework и URI выбранной директории;
- внутреннее хранилище приложения: для пустого каталога заметок и будущей синхронизации;
- JVM: обычная файловая система;
- iOS: отдельная реализация в sandbox приложения;
- tresse-sync: адаптер удалённого хранилища после фиксации API-контракта.

### 3.3. Слои

- `domain`: модели, use cases, фильтры, правила задач;
- `notesdirectory`: абстракции хранилища, Markdown parser/patcher;
- `index`: локальный индекс и инкрементальная переиндексация;
- `sync`: интерфейс и реализация синхронизации;
- `presentation`: общий Compose Multiplatform UI;
- Android-модули: SAF, WorkManager/alarms, notifications, Glance widgets;
- будущие platform-модули: Wear OS, iOS, desktop.

### 3.4. Минимально инвазивный формат

- существующие заметки не перемещаются и не переписываются целиком без необходимости;
- задачи распознаются по Markdown checkbox: `- [ ]`, `- [x]` и согласованному подмножеству атрибутов;
- приложение изменяет только конкретную строку задачи, если файл не поменялся с момента чтения;
- быстрые заметки и чек-листы хранятся в выбранной пользователем папке;
- служебные данные приложения не добавляются в пользовательские файлы без необходимости;
- папка быстрых чек-листов исключается из индекса задач.

## 5. Сквозные критерии качества

### Надёжность данных

- Любая запись проверяет, что исходный файл не был неожиданно изменён.
- При конфликте сохраняется возможность восстановить обе версии.
- Индекс всегда можно удалить и полностью восстановить из каталога заметок.
- Служебная БД никогда не становится единственной копией пользовательской заметки.

### Производительность

- Файловые и сетевые операции выполняются вне main thread.
- Списки используют lazy-компоненты и стабильные ключи.
- Повторная индексация пропускает неизменённые файлы.
- Performance budget фиксируется после теста на реальном целевом каталоге заметок.

### Безопасность и приватность

- Доступ запрашивается только к выбранной директории.
- Токены хранятся в защищённом platform storage.
- Содержимое каталога заметок не попадает в analytics и crash logs.
- Сетевой sync работает только по TLS и не включается без действия пользователя.

### Тестирование

- `commonTest`: domain, parser, patcher, filters, conflict rules.
- Android unit/instrumentation: SAF adapter, WorkManager, notifications.
- Screenshot/UI tests: ключевые экраны и состояния.
- Widget tests: конфигурация, actions, process restart.
- End-to-end fixtures: пустой каталог заметок, существующий каталог заметок, внешние изменения, конфликт.

## 6. Приоритеты backlog

### P0 — обязательный Android MVP

- Android SAF-доступ к каталогу заметок;
- parser, patcher и индекс;
- задачи на день/неделю;
- фильтры по файлу/папке;
- создание и выполнение задачи;
- быстрые заметки и чек-листы;
- Android-виджеты;
- локальные уведомления;
- APK-релиз.

### P1 — после первого рабочего релиза

- tresse-sync, если discovery подтверждает пригодность API;
- улучшенный синтаксис emoji/dataview формата задач;
- дополнительные фильтры и сортировки;
- Wear OS Tiles/Complications;
- публикация в Google Play.

### P2 — отдельные продуктовые этапы

- iOS и WidgetKit;
- desktop-дистрибуция;
- системные интеграции и share targets;
- расширенный редактор заметок.

## 7. Рекомендуемая последовательность релизов

1. **Technical alpha:** этапы 0–5, работа с реальным каталогом заметок без полноценного UI.
2. **Feature alpha:** этапы 6–8, все основные операции внутри приложения.
3. **Android beta:** этапы 9–10, виджеты и уведомления.
4. **Sync beta:** этап 11, только если tresse-sync прошёл discovery.
5. **MVP 1:** этап 12, подписанный APK.

## 8. Предварительная оценка

Для одного разработчика при полной занятости:

| Блок | Оценка |
|---|---:|
| Спецификация, инфраструктура, архитектура | 1–2 недели |
| Каталог заметок, parser, patcher, индекс | 3–5 недель |
| Основной UI задач и заметок | 2–3 недели |
| Android-виджеты и уведомления | 2–4 недели |
| Стабилизация и релиз | 1–2 недели |
| tresse-sync после готового API-контракта | дополнительно 2–5 недель |

Итого без синхронизации: ориентировочно **9–16 недель**. Оценка уточняется после этапов 0, 4 и discovery tresse-sync.

Wear OS, iOS и desktop в эту оценку не входят.
